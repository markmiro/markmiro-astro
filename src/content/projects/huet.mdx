## Summary

A theming library for accessible colors. Instead of picking colors, you pick how much contrast each element has against its background, and Huet calculates the colors for you. It recolors images to match the theme too.

I started it as a React library in 2018 and rebuilt it in 2026 to work with any framework.

- [Demo](https://markmiro.github.io/huet)
- [The shadcn/ui site themed with Huet](https://shadcn-huet.vercel.app)

This website's colors come from Huet too. Try the theme picker in the top-right corner.

## Motivation

It's often assumed that re-branding a website is easy. In practice, there's a big risk of accidentally creating an unpredictable number of contrast issues. This will tend to happen in parts of the UI that are often not tested, or are difficult to test, like error states—which is especially tragic.

## Goals

Instead of letting the developer define the colors they want in the UI. Instead, they define the contrast they want. If you're adding a button on top of a black page, instead of saying you want a white button, you instead say "I want a button with 100% contrast against the background".

<div class="no-prose">
  <div class="bg-black p-6 text-center">
    <button class="bg-white text-black px-3 py-1 rounded-md">Button</button>
  </div>
</div>

```jsx
<Container bg="black">
  <Button bgContrast="100%" textContrast="100%">
    Button
  </Button>
</Container>
```

In the above code, the color dependencies look like this:

```
container background <- button background <- button text
```

Text is calculated off of the button's background which is calculated off of the container's background.

If we change the background `bg="white"`, we want all the children to update recursively.

<div class="no-prose">
  <div class="bg-white p-6 text-center border">
    <button class="bg-black text-white px-3 py-1 rounded-md">Button</button>
  </div>
</div>

```jsx
<Container bg="white">
  <Button bgContrast="100%" textContrast="100%">
    Button
  </Button>
</Container>
```

## Rebuild (2026)

In October 2026 I picked Huet back up and rewrote it in TypeScript. The core no longer depends on React. A theme is plain JSON: a neutral ramp from darkest to lightest, plus anchor colors for red, yellow, green, blue and purple. Elements get their contrast from a class name, and Huet works out each color from the element's parent background.

```html
<section class="huet-bg-20">
  <p class="huet-text-60">Manage your profile.</p>
  <button class="huet-bg-blue-20">Save changes</button>
  <img data-huet-recolor src="/photo.jpg" alt="" />
</section>
```

```ts
import { mountTheme, themes } from "huet";
import { mountImages } from "huet/images";

const colors = mountTheme(root, themes.Paperback);
const images = mountImages(root, themes.Paperback);

// Dark mode is the same theme with the background at the dark end of its ramp
colors.update(themes.Paperback, { background: 0 });
```

What it does now:

- **Contrast with APCA.** Text colors are solved for readability with APCA, instead of WCAG 2 contrast ratios.
- **Image and SVG recoloring.** Each pixel is read as a position on the default ramps and moved to the same position on the theme's ramps. Each theme is baked into a 3D lookup table and applied on the GPU with WebGL2, with a CPU fallback.
- **Framework support.** It works with React, Vue, Svelte and Astro, and has a Tailwind v4 bridge, a Shiki theme for code blocks, and styles for native form controls. Pages rendered at build time can get a theme as plain CSS variables, which is how this site uses it.
- **A theme configurator.** `huet-react` has a panel for picking presets and editing a theme's colors, contrast, signal lightness and image settings. It floats in a corner or opens from a button, and this site's theme picker is that panel.
- **A real-world test.** To see how far it goes, I themed the whole [shadcn/ui site](https://shadcn-huet.vercel.app) with Huet, including its charts, code blocks, logos and images.

## Learnings

The biggest learning was I didn't have a set of people that wanted to use it. I figured I'd build it because I wanted something like this, but the complexity involved in building it was higher than the benefits I gained.
